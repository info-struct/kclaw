# KClaw Helm Installer

Deploy KClaw to an **existing Kubernetes cluster** via a single `helm install`.

> **Not what you're looking for?** If you want a turnkey single-node setup from a bare Linux machine, use the k3s installer in the repo root (`kclaw-installer.tar.gz`). This chart is for teams that already have a cluster.

---

## What this installs

| Component | What it does |
|---|---|
| **PostgreSQL** | Backing store for LiteLLM (`postgres:16-alpine` StatefulSet) |
| **LiteLLM** | Model proxy — routes to Anthropic, Bedrock, or OpenRouter |
| **CredRouter** | Encrypted credential vault, JWT IAM, per-tenant config |
| **Orchestrator** | Message routing, agent pod lifecycle, Admin API |
| **Admin UI** | Web dashboard — tenants, teams, sessions, MCP servers |

All secrets are auto-generated by the chart on first install and persisted in a Kubernetes Secret so upgrades are stable.

## Prerequisites

| Requirement | Notes |
|---|---|
| Kubernetes 1.24+ | Tested on EKS, GKE, k3s, RKE2 |
| Helm 3.10+ | `helm version` |
| A dedicated node | KClaw pins components to one node (SQLite + hostPath storage) |
| RWO storage class | Default: `local-path`. Any `ReadWriteOnce` class works. |
| Ingress controller | nginx, Traefik, etc. You supply the class name. |
| Slack app | Bot Token (`xoxb-…`) + App Token (`xapp-…`) in Socket Mode. See [Slack setup](#slack-setup). |
| LLM provider credentials | Anthropic API key, AWS Bedrock keys, or OpenRouter API key |

### local-path storage

If your cluster doesn't already have a `local-path` storage class, install Rancher's provisioner (works on any cluster, not just k3s):

```bash
kubectl apply -f https://raw.githubusercontent.com/rancher/local-path-provisioner/master/deploy/local-path-storage.yaml
```

This provisions storage on whichever node the pod schedules to — which is why the node pin matters.

### Cloud provider notes

KClaw pins all components to a single node (SQLite + hostPath agent workspaces). Multi-node scheduling is an Enterprise Edition feature. Pick any node in your cluster, label it, and set `node:` to its `kubernetes.io/hostname` value.

**EKS**
```yaml
storageClass: gp3          # or gp2
ingress:
  className: nginx         # install aws-load-balancer-controller or nginx-ingress first
```

**GKE**
```yaml
storageClass: standard-rwo
ingress:
  className: nginx         # install nginx-ingress-controller first
```
Note: GKE Autopilot does not support hostPath volumes — use a Standard cluster.

**RKE2 / Rancher**
```yaml
storageClass: local-path   # available by default on RKE2
ingress:
  className: nginx         # or traefik if installed
```

**k3s**
```yaml
storageClass: local-path   # available by default
ingress:
  className: traefik       # available by default
```

### Node sizing

Each agent pod requests 512Mi RAM and 100m CPU. Fixed components (LiteLLM, Orchestrator, CredRouter, Admin UI, PostgreSQL) consume ~1.3Gi combined. For 30 concurrent agents:

```
30 × 512Mi + 1.3Gi ≈ 16.5Gi memory required
```

Recommended minimum for 30 agents (64Gi gives comfortable headroom):

| Cloud | Instance | vCPU | RAM | Arch |
|---|---|---|---|---|
| AWS | `r8g.2xlarge` | 8 | 64Gi | ARM64 (Graviton4) |
| AWS | `m7g.4xlarge` | 16 | 64Gi | ARM64 (Graviton3) |
| AWS | `m7i.4xlarge` | 16 | 64Gi | x86 |
| GCP | `t2a-standard-16` | 16 | 64Gi | ARM64 (Ampere Altra) |
| GCP | `n2-highmem-8` | 8 | 64Gi | x86 |

ARM64 instances are recommended — all KClaw images are multi-arch and ARM64 is typically 15-20% cheaper than equivalent x86.

## Quick start

### 1. Label your dedicated node

All KClaw components will schedule here. Pick one node and label it:

```bash
kubectl label node <your-node-name> kclaw-node=true
```

Verify:
```bash
kubectl get nodes --show-labels | grep kclaw-node
```

### 2. Add the Helm repo

```bash
helm repo add kclaw https://info-struct.github.io/kclaw/helm-installer
helm repo update
```

### 3. Create your values file

```yaml
# my-values.yaml

node: your-node-name        # must match the node you labeled above

admin:
  email: you@example.com
  name: "Your Name"

slack:
  enabled: true
  botToken: "xoxb-..."      # from Slack API portal
  appToken: "xapp-..."      # Socket Mode app-level token

llm:
  provider: openrouter      # anthropic | bedrock | openrouter
  openrouter:
    apiKey: "sk-or-v1-..."
    model: "google/gemini-3.8-flash"

# Optional: web search inside agent conversations
braveSearch:
  apiKey: "BSA..."

# Optional: Whisper voice transcription for Slack voice messages
openai:
  apiKey: "sk-..."
```

### 4. Install

```bash
helm install kclaw kclaw/kclaw \
  --namespace kclaw --create-namespace \
  -f my-values.yaml \
  --wait --timeout=15m
```

The `--wait` flag blocks until all deployments and the bootstrap Job complete. First install takes ~5 minutes (image pulls + LiteLLM Prisma migrations).

### 5. Access the Admin UI

```bash
# Get the node IP
kubectl get nodes -o wide | grep <your-node-name>
```

Then open `http://<ingress-host>` (e.g. `http://kclaw-admin-ui.local`) and log in with the email you configured. Your temporary password is stored in the generated secrets:

```bash
kubectl get secret -n kclaw kclaw-generated-secrets \
  -o jsonpath='{.data.admin-password}' | base64 -d
```

Change your password on first login.

## Values reference

### Required

```yaml
node: ""                    # kubernetes.io/hostname of your dedicated node

admin:
  email: ""                 # Admin UI login email
  name: ""                  # Display name shown in UI
```

### Messaging channels

```yaml
slack:
  enabled: false
  botToken: ""              # xoxb-...
  appToken: ""              # xapp-...
```

### LLM provider

```yaml
llm:
  provider: anthropic       # anthropic | bedrock | openrouter
  assistantName: "G-eves"   # How the bot refers to itself

  anthropic:
    apiKey: ""

  bedrock:
    accessKeyId: ""
    secretAccessKey: ""
    region: us-east-1
    # Optional: direct Anthropic fallback when Bedrock is unavailable
    anthropicFallbackKey: ""

  openrouter:
    apiKey: ""
    model: google/gemini-3.8-flash
```

### Multi-model routing (OpenRouter)

When using `provider: openrouter`, KClaw configures two models and an auto-router in LiteLLM:

| LiteLLM name | Values field | Role |
|---|---|---|
| `openrouter-primary` | `llm.openrouter.model` | Text and general conversation |
| `openrouter-document` | `llm.openrouter.documentModel` | PDFs, images, and complex tasks |
| `primary` | _(auto-router)_ | Routes to the above two automatically |

Agents always send `model: primary` — LiteLLM dispatches to the right model based on message content. Both models use the same `apiKey`.

**Configuration**

```yaml
llm:
  provider: openrouter
  openrouter:
    apiKey: "sk-or-v1-..."
    model: "google/gemini-3.8-flash"            # primary: text and conversation
    documentModel: "anthropic/claude-haiku-4-5" # secondary: PDFs, images, complex tasks
```

Swap either model independently. Examples:

```yaml
# Cost-optimised: DeepSeek for text, Haiku for documents
model: "deepseek/deepseek-v4.1-flash"
documentModel: "anthropic/claude-haiku-4-5"

# High quality: Sonnet for text, Opus for complex tasks
model: "anthropic/claude-sonnet-4-6"
documentModel: "anthropic/claude-opus-4-5"

# Fully open: Gemini Flash for text, Gemini Pro for documents
model: "google/gemini-3.8-flash"
documentModel: "google/gemini-pro-1.5"
```

**Applying a model change**

```bash
helm upgrade kclaw kclaw/kclaw \
  --namespace kclaw \
  -f my-values.yaml

kubectl rollout restart deployment/litellm -n kclaw
kubectl rollout status deployment/litellm -n kclaw
```

### Ingress

```yaml
ingress:
  className: nginx          # traefik | nginx | or your controller's class name
  adminUI:
    enabled: true
    host: kclaw-admin-ui.local
    # annotations: {}       # add TLS, auth, etc. here
  adminApi:
    enabled: true
    host: kclaw-admin.local
```

For TLS with cert-manager:

```yaml
ingress:
  className: nginx
  adminUI:
    host: kclaw.example.com
    annotations:
      cert-manager.io/cluster-issuer: letsencrypt-prod
    tls:
      - secretName: kclaw-tls
        hosts:
          - kclaw.example.com
  cookieSecure: "true"      # set true when serving over HTTPS
```

### Secrets (optional overrides)

The chart auto-generates all secrets on first install. Leave these blank unless you need to bring your own (e.g., restoring from backup):

```yaml
secrets:
  encryptionKey: ""         # base64, 32 bytes  — openssl rand -base64 32
  jwtSecret: ""             # base64, 48 bytes  — openssl rand -base64 48
  adminToken: ""            # hex, 32 bytes     — openssl rand -hex 32
  litellmMasterKey: ""      # auto-prefixed sk-litellm-...
  postgresPassword: ""      # hex, 16 bytes
```

Once installed, these are stored in the `kclaw-generated-secrets` Secret in the `kclaw` namespace and reused on every upgrade.

### PostgreSQL

A minimal `postgres:16-alpine` StatefulSet is included. It pins to the same node as all other KClaw components via `.Values.node`.

```yaml
postgresql:
  enabled: true             # set false to bring your own PostgreSQL
  image: "postgres:16-alpine"
  externalHost: ""          # required if postgresql.enabled is false
  auth:
    database: litellm
  primary:
    persistence:
      size: 5Gi
```

### Image overrides (Enterprise Edition)

CE images are used by default. Override for EE or a private registry:

```yaml
images:
  credrouter:   infostructkclaw/kubeclaw-credrouter:latest
  orchestrator: infostructkclaw/kubeclaw-orchestrator:latest
  agent:        infostructkclaw/kubeclaw-agent:latest
  adminUI:      infostructkclaw/kclaw-admin-ui:latest
  pullSecret:   ""   # name of an existing imagePullSecret in the kclaw namespace
```

## Upgrading

```bash
helm upgrade kclaw kclaw/kclaw \
  --namespace kclaw \
  -f my-values.yaml \
  --wait
```

Auto-generated secrets are preserved across upgrades via the `lookup` function — the chart reads the existing `kclaw-generated-secrets` Secret and reuses its values rather than re-generating.

The bootstrap Job only runs on first install (`helm.sh/hook: post-install`). It does not re-run on upgrade.

---

## Uninstalling

```bash
helm uninstall kclaw --namespace kclaw
kubectl delete namespace kclaw
```

PVCs and the generated secrets are not deleted by default (`helm.sh/resource-policy: keep`). To remove all data:

```bash
kubectl delete pvc -n kclaw --all
kubectl delete secret -n kclaw kclaw-generated-secrets
```

If using `local-path` storage, the data directory on the node is also not automatically cleaned up:

```bash
ssh <node> "sudo rm -rf /var/lib/rancher/k3s/storage/pvc-*_kclaw_*"
```

## Architecture notes

### Why one dedicated node?

CredRouter stores credentials in SQLite and the Orchestrator uses a hostPath for agent workspaces. Both require the pod to always land on the same node. Multi-node scheduling (shared PVCs across nodes) is an Enterprise Edition feature.

### How bootstrap works

On first install, a post-install Helm hook Job:
1. Waits for LiteLLM readiness, then generates a virtual API key
2. Stores the key as a Kubernetes Secret
3. Connects to CredRouter and initializes the tenant database
4. Creates the default provider config (pointing at LiteLLM)
5. Creates the first admin user — temporary password stored in `kclaw-generated-secrets`

### LiteLLM

LiteLLM runs in the `kclaw` namespace as a ClusterIP service. Access its UI via port-forward:

```bash
kubectl port-forward -n kclaw svc/litellm 4000:4000
# open http://localhost:4000/ui
```

## Troubleshooting

**Bootstrap Job failed**
```bash
kubectl logs -n kclaw -l app=kclaw-bootstrap
```

**LiteLLM not ready (image pull or Prisma migration slow)**
```bash
kubectl logs -n kclaw -l app=litellm
# Normal: Prisma migrations take ~2 min on first start
```

**CredRouter CrashLoopBackOff**
```bash
kubectl describe pod -n kclaw -l app=credrouter
# Check PVC is bound: kubectl get pvc -n kclaw
```

**Ingress not routing**

Check your ingress class matches what's installed:
```bash
kubectl get ingressclass
```

Update `ingress.className` in your values file to match.
